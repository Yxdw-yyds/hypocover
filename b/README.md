# 模块 B：双射高度向量表示与紧预算简单偏好分析

> **所属模块**：输出表示空间（Output Representation Space）  
> **代码目录**：`b/`、`repro/`  
> **评测模型**：OpenRouter `deepseek/deepseek-v4-flash-0731`（`temperature=0.7, top_p=0.8, max_tokens=512, reasoning=false`，与官方 512 基线完全一致）

---

## 1. 核心思想与方法

官方协议要求模型直接输出逐层 $3\times 3$ 的 `0/1` 体素文本，存在两个结构性缺陷：
1. **输出空间包含大量非法解**（第一层全 0、悬空方块、格式错位）；
2. **输出冗长**（基线中 21.3% 的回答触及 512-token 上限被截断）。

利用重力约束与列独立结构性质，我们将合法三维结构无损压缩为**高度向量（Height Vector）**：
$$H = (h_1, h_2, \dots, h_k) \in \{1, 2, 3\}^k, \quad |H_O| = 3^k \in \{9, 27\}$$
其中 $h_i$ 为按行扫描顺序第 $i$ 个占用格的柱高。该表示与合法三维体素结构构成严格**双射**（由 `b/check_bijection.py` 在全部 120 题上验证 0 误差）：
- 任意高度向量均天然满足俯视投影一致与重力支撑，**物理合法率（VR）恒为 100%**；
- 单次输出仅十余个 token，**完全消除长度截断**；
- 本地通过确定性映射（第 $l$ 层在位置 $p$ 为 `1` $\iff h_p \ge l$）还原为官方逐层体素文本，交由同一官方 `score_predictions.py` 评分。

在此表示上对比两种引导策略：
- **`free`**：列出已发现的高度向量历史，仅要求输出一个与历史不同的新向量；
- **`coord_fixed`**：除历史去重外，按轮次依次要求新向量至少在第 $1, 2, \dots, k$ 个坐标上与已发现向量不同。

### 2.2 成本、截断与解析细节审计

| 指标（验证 + 测试共 648 次调用） | 官方逐层基线 | 高度向量 `free` |
|---|---:|---:|
| API 总费用 | \$0.1176 | **\$0.0177（降至 1/6.6）** |
| 触及 512-token 截断 | 138 条（21.3%） | **0 条（0.0%）** |
| 解析失败 | ~4.5% | **0 条（0.0%）** |
| 重复生成次数 | ~30% | **0 / 648** |

- **自由文本尾答案解析修正**：初版解析器提取模型回复中的*第一个* `H=(...)`，在 `g3_h3_b3_079` 第 27 轮误抓取了模型正文中核对已出现候选时提到的 `H=(1,1,1)`，而模型末行实际给出的最终答案为缺失解 `H=(3,2,3)`。修复 `b/representation.py:parse_vec` 为提取**最后一个完整向量**并从原始保存响应离线重放后（`repro/verify_free_100.py`），648 次调用实现 0 重复，验证与测试 RR 均为 **100.00%**。
- **`free` 优于 `coord_fixed`**：强制指定某一坐标不同偶尔会将模型推向其他已出现的组合，说明静态轮流约束不如让模型直接全局检索紧凑历史。

## 3. 紧预算下的简单偏好（Simplicity Bias）发现

虽然满预算（$N=|H_O|$）下 `free` 达到 100%，但对 36 道题轨迹的前 $k$ 步做离线复杂度分层统计（按总方块数 $\sum h_i$ 划分为低/中/高三档，`repro/check_free_complexity_bias.py`）揭示了显著的**简单结构优先偏置**：

| 题型 | 截断预算 $B$ | 前 $B$ 步平均方块数（全集均值） | 低复杂度覆盖率 | 高复杂度覆盖率 |
|---|---:|---:|---:|---:|
| 三列题（27 解） | 9 | 5.02（6.00） | 66% | **7%** |
| 三列题（27 解） | 13 | 5.23（6.00） | 85% | **17%** |
| 三列题（27 解） | 26 | 5.92（6.00） | 99% | 90% |
| 两列题（9 解） | 4 | 3.40（4.00） | 78% | **19%** |

模型在生成初期像里程表一样优先枚举低矮结构，高复杂度假设在紧预算下严重欠采样。
